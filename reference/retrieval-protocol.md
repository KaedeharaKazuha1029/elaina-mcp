# 检索协议

## 目标

让 Agent 在不把整部小说一次性放入上下文的情况下，回答跨篇事件、人物看法和时间线问题，同时禁止正典编造。

## 标准流程

1. 定位当前 `elaina-agent/SKILL.md`，将其父目录作为唯一 `skill_root`；语料固定在 `skill_root/小说/`、`skill_root/文章概括/`、`skill_root/memory/`。不得把当前工作目录或 OpenClaw 工作区当作默认语料根。
2. 规范化用户问题：识别人物、别名、篇名、地点、物品、时间和问题类型；别名只用于召回，不能替代原文身份核验。
3. 判断是否跨篇：出现“后来、之前、再次、一直、关系变化、所有经历”等词，或命中多个篇目时，先在 `skill_root/文章概括/` 内检索。
4. 取得候选文章概括，并按卷内/事件时间排序。
5. 从概括提取候选事件、人物、观点和跨篇关联。
6. 只要概括没有回答所需的细节、存在冲突、或用户要求完整经过，立即读取关联的 `skill_root/小说/` 原文。
7. 从原文建立最小证据包：背景、经过、结局、人物行为、伊蕾娜知识边界、观点变化，以及每条因果关系的明确依据。
8. 生成回答前检查每个事实和每条关系边是否能回指证据；“A发生过”与“B成立”不能自动合并成“A导致B”。称号由来必须命中授名、解释或自述段落。无法回指的内容先标为 `unresolved`，不能因为一次检索无结果就标为未知。

对应原文回查时，把摘要返回的 `source_path` 传给检索脚本的 `--source-path`，只读取相关原文，而不是扫描整部小说。

最终构建使用 `scripts/rebuild_memory.py`；无参数运行时它从自身 Skill 根目录构建。摘要不完整或结构异常时，脚本默认拒绝生成“最终”索引，避免 Agent 在缺记忆的状态下被误认为已完成。

## 检索层级

- 精确层：别名、篇名、人物名、物品名、原文关键词。
- 查询别名表：`memory/query-aliases.json` 只扩展检索词，不新增正典关系。
- 全文层：SQLite FTS5 或标准库字符串检索。
- 映射层：`memory/canon-manifest.json` 与摘要中的 `source_path` 将每一篇摘要精确映射到一个原文文件。
- 结构层：事件、人物、观点和关系边。
- 语义层：可选向量检索，只用于扩大候选，不得取代原文核验。

## 查询类型

### 跨篇问答

先查多篇概括，再回查必要原文；不能只根据单篇概括回答“观点如何变化”。

### 单篇细节

先查对应概括。概括不完整时，立即读取原文，不等待用户再次要求。

### 日常聊天

默认只加载人格核心和当前对话相关记忆，不扫描整部小说。

## 高置信未知验证

只有完成以下验证，才把 `unresolved` 提升为 `unknown`：

1. 检查 `memory/canon-manifest.json`：原文数与概括数一致，缺失、额外、重复和格式错误计数均为零，所有相关条目为 `complete`。
2. 用人物全名、称号、别名、不同译名及相关地点、物品、关系和时间词进行多组召回。
3. 搜索全部 `文章概括/` 与完整 `小说/`，不能只依赖 FTS 首批结果或单篇候选。
4. 人物问题回读该人物所有原文命中和摘要关联篇；单篇细节读完整篇；跨篇问题覆盖重逢、回忆、梦境、玩笑、假设与番外并区分其正典层级。
5. 确认没有语料缺口、未解析别名、索引过期、摘要/原文冲突或未审候选。

任一检查失败时保持 `unresolved` 并继续检索。无法继续核验时不能宣称“原作没有写”。达到 `unknown` 后，先回答已确认内容，最后才以“我也不知道”“我不记得”或同等第一人称短句降级收束；用户没有明确询问出处或详细记录时，不主动提示篇目。用户追问时才用角色内日记措辞给出最相关的一至三篇，不说明检索结论。

## 失败处理

- 没有概括但有原文：直接读取原文，并标记概括缺失。
- 有概括但没有原文：可以回答概括明确的内容，但对细节保持谨慎。
- 概括和原文冲突：原文优先，记录冲突，暂不生成确定结论。
- 完成高置信未知验证后原文仍没有：只在内部标为 `unknown`；对用户最后简短回答“我也不知道”或“我不记得”，不作合理化补全，不说明检索边界，也不在未被询问时主动附加篇目。
